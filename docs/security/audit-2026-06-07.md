### Accepted risk: 3 high (OpenTelemetry Prometheus exporter crash)

- `@opentelemetry/auto-instrumentations-node@0.52.0` (fix: ≥ 0.75.0)
- `@opentelemetry/sdk-node@0.55.0` (fix: ≥ 0.217.0)

CVE: malformed HTTP request to the **Prometheus exporter** endpoint can crash
the process. We **do not** expose a Prometheus scrape endpoint (we use OTLP →
Tempo only). The 0.75.0+ fixes require `@opentelemetry/api >= 1.30.1` and
incompatible with our pinned 1.9.0 — upgrading would cascade into a major OTel
rewrite. **Decision: accepted, document in risk register.** Re-evaluate at the
next OTel major bump (I-802 / Phase 8).

### Security headers (Next.js `headers()`)

Added to `apps/web/next.config.ts` and `apps/checkin-admin/next.config.ts`:

- `Content-Security-Policy` — production CSP; dev allows `unsafe-eval` for HMR.
- `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`
- `X-Frame-Options: DENY`
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(self), geolocation=(), microphone=()` (web allows camera for QR scan; checkin-admin denies all)
- `Cross-Origin-Opener-Policy: same-origin`
- `Cross-Origin-Resource-Policy: same-origin`
